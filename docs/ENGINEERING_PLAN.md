# Quant Lab 后续搭建流程

## 产品定位

Quant Lab 是一个多用户内部量化研究平台。当前第一阶段先完成数据中心；后续会扩展到研究过程沉淀、策略研究、任务管理和报告生成。

## 阶段 0：工程地基

- 保持前后端模块边界清楚。
- 前端应用壳层、认证、API 客户端、业务模块分开。
- 后端路由、服务、数据源 provider 分开。
- 每个新增业务模块都要有自己的入口、组件、组合逻辑和说明文档。

## 阶段 1：数据中心模块

当前优先完成并稳定：

- 标的列表和搜索。
- 管理员录入标的。
- Tushare 数据源配置。
- 标的同步。
- 日线/周线行情展示。
- K 线、成交量、均线、BOLL、RSI、MACD。
- 策略因子展示。
- 最近行情表。

## 阶段 2：多用户内部平台能力

数据中心稳定后，再补齐平台级能力：

- 用户管理。
- 角色权限。
- 操作日志。
- 同步日志页面。
- 数据源状态检查。
- 数据质量诊断。

## 阶段 3：研究过程沉淀

进入本阶段前，需要先讨论并确认，不直接实现。

需要先聊清楚：

- 研究对象：围绕标的、组合、策略，还是主题。
- 研究记录：像笔记、实验日志、结论卡片，还是任务流。
- 策略对象：是筛选规则、信号、回测配置，还是完整策略工程。
- 多用户协作：是否需要评论、共享、权限隔离。
- 数据模型：研究条目、假设、观察、图表快照、附件、结论如何关联。

## 阶段 4：策略与回测

本阶段必须在阶段 3 讨论后再启动。

初步方向只作为占位：

- 策略草稿。
- 条件表达。
- 回测任务。
- 回测结果归档。
- 与研究记录互相引用。

## 阶段 5：部署和运维

- 本地一键启动和停止脚本。
- 健康检查脚本。
- Docker Compose 部署。
- Nginx/HTTPS。
- SQLite 与数据文件备份。
- 服务器恢复流程。
